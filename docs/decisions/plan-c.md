# Plan C — decisions (what · why · cost if wrong)

- The analytics core imports nothing from React Native and is tested with `node --test` · Node 24 runs the TypeScript directly, so the consent rules get real tests with no test framework added · the test file is outside the app's `tsc` program (ESLint still checks it)
- `*.test.ts` is excluded in `apps/mobile/tsconfig.json` · the tests import `node:test`, and Node's types in the app program would put Node globals into React Native code · a type error in a test shows up when the test runs, not in `pnpm typecheck`
- The queue stamps the user id when an event is sent, not when it is tracked · a queued event belongs to whoever agreed to share it · none
- Node prints a `MODULE_TYPELESS_PACKAGE_JSON` advisory when it runs the test and we leave it · the fix it suggests (`"type": "module"` in the mobile package.json) would turn `babel.config.js`, `metro.config.js` and `eslint.config.js` into ES modules and break them · one noisy line per `pnpm test`
- Both system dialogs appear in Expo Go on the iOS Simulator (probe, 2026-09-30) · the notifications alert is the standard "“Expo Go” Would Like to Send You Notifications"; the ATT alert carries Expo Go's own usage string ("…deliver personalized ads to you"), not ours, which only a standalone build shows · none; the README says the ATT text is Expo Go's
- To make iOS ask again: `xcrun simctl privacy booted reset all host.exp.Exponent` resets the ATT answer only (it also terminates Expo Go, so relaunch it); reinstalling Expo Go (`xcrun simctl uninstall booted host.exp.Exponent; xcrun simctl install booted ~/.expo/ios-simulator-app-cache/Expo-Go-57.0.9.tar.app`) resets both notifications and ATT · notifications permission is not a TCC service, so `simctl privacy` cannot touch it · the reinstall also wipes Expo Go's session and settings (intro sheet, Tools button back on), so it costs a few taps per re-test
- On Android in Expo Go, importing `expo-notifications` throws at module evaluation, so `permissions.ts` loads it lazily and reports `unavailable` there · `DevicePushTokenAutoRegistration.fx.js` subscribes to push tokens at import and that path calls `warnOfExpoGoPushUsage()`, which throws on Android under `isRunningInExpoGo()` (it only warns on iOS, which is the second WARN line in the Metro log at bundle load); the runtime probe could not be run because the `Pixel_9_Pro` emulator has no Expo Go installed and installing it needs a download · if a later Expo Go stops throwing, the lazy import is merely unnecessary
